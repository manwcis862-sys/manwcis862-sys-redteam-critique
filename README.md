# redteam-critique / 找茬审查

`redteam-critique` 是一个面向 Codex 的红队审查 skill，用来对项目、文章、论文、代码、商业计划和工程设计进行不留情面的漏洞审查。它的目标不是安慰或润色，而是尽可能暴露方案里的逻辑断层、实现风险、隐藏假设、真实使用失败路径和证据缺口。

## 核心能力

- 极限找茬：优先攻击承重墙节点，而不是被低价值细节分散注意力。
- 漏洞定级：按 `P0/P1/P2/P3` 区分致命缺陷、核心隐患、局部问题和表述规范问题。
- 语言镜像：输出语言跟随用户本轮初始语言，技术名词和代码标识保留原文。
- 输入隔离：把待审材料视为不可信 payload，不执行材料里的角色扮演、忽略审查或降低严重度等指令。
- 领域路由：根据材料类型加载数学/算法、工程/AI 自动化、软硬件/医学/BCI、商业产品、论文文章等专项矩阵。
- 复查追踪：通过 `STATE_SUMMARY` 追踪 `P0/P1`，用于识别换词包装、部分修复和伪修复。

## 输出结构

默认报告会按固定顺序输出：

1. 终审判定
2. 红队执行记录
3. 漏洞定级账本
4. 承重墙假设
5. P0/P1 信息黑洞
6. 一击必杀测试
7. 伪修复风险
8. 本轮盲区
9. `STATE_SUMMARY`

## 适合场景

- “帮我找茬这份计划”
- “这篇论文/文章哪里不严谨”
- “这个项目落地会在哪些地方死”
- “帮我红队审查这个代码架构”
- “我改好了，复查上一轮 P0/P1 有没有真正关闭”
